## 一、后端接口返回格式统一说明

### 1.1 后端返回格式汇总

后端使用了多种返回格式，前端需要兼容处理：

#### 格式 1：标准格式（使用 response.js）
```javascript
// 成功
{ code: 200, message: "成功", data: {...} }

// 失败
{ code: 0, message: "失败原因" }
```

**使用此格式的接口：**
- `GET /users/me` - 当前用户信息
- `GET /points/goods` - 商品列表
- `GET /points/goods/:id` - 商品详情
- `POST /points/orders` - 创建订单
- `GET /points/orders` - 订单列表
- `GET /points/token/log` - 积分流水
- `GET /wechat/userinfo/:openid` - 微信用户信息（成功时）
- `GET /swiper` - 轮播图列表

#### 格式 2：无 code 字段（旧接口）
```javascript
{
  message: "成功",
  data: [...],
  pagination: {
    page: 1,
    pageSize: 10,
    total: 100,
    totalPages: 10
  }
}
```

**使用此格式的接口：**
- `GET /articles` - 文章列表
- `GET /articles/top` - 热门文章

#### 格式 3：只有 data 字段
```javascript
{
  data: {...}
}
```

**使用此格式的接口：**
- `GET /wechat/openid/:code` - 获取 openid

### 1.2 前端统一处理方案

**文件：** `utils/request.js`

```javascript
if (res.statusCode === 200) {
  const responseData = res.data
  
  // 1. 标准格式：{ code: 200, data, message }
  if (responseData.code === 200) {
    // 如果有 token，返回完整响应
    if (responseData.token) {
      resolve(responseData)
    } else {
      resolve(responseData.data)
    }
  }
  // 2. 失败：{ code: 0, message }
  else if (responseData.code === 0) {
    reject(responseData)
  }
  // 3. 无 code 字段：{ data, message, pagination }
  else if (!responseData.code && responseData.data !== undefined) {
    if (responseData.pagination) {
      resolve({
        list: responseData.data,
        total: responseData.pagination.total
      })
    } else {
      resolve(responseData.data)
    }
  }
  // 4. 只有 data 字段
  else if (responseData.data && Object.keys(responseData).length === 1) {
    resolve(responseData.data)
  }
  // 5. 未知格式
  else {
    reject(responseData)
  }
}
```

## 二、微信登录问题（已解决）

### 2.1 响应格式判断错误

**问题**：用户微信登录后没有跳转，`userInfo = null`

**原因**：
- 后端返回 `code: 0` 表示用户不存在（失败）
- 前端错误地把 `code: 0` 当成功处理

**解决方案**：
- `code: 200` 才是成功，返回 data
- `code: 0` 是失败，reject

## 三、首页/商城/我的页面数据展示问题（已解决）

### 3.1 数据解析不统一

**问题**：
- 首页没有数据
- 我的页面没有显示用户信息
- 积分商城没有数据
- 积分流水没有数据

**原因**：
- 后端返回格式不统一
- 前端只处理 `code: 200`，其他格式都失败

**解决方案**：
统一在 `request.js` 中处理所有格式，自动转换为前端需要的格式

## 五、开发注意事项

### 5.1 响应处理规范

- **code: 200** - 成功，返回 data
- **code: 0** - 失败，reject
- **无 code** - 旧接口，返回 data
- **有 token** - 返回完整响应（登录接口）

### 5.2 数据结构转换

```javascript
// 文章列表：{ data, pagination } → { list, total }
if (responseData.pagination) {
  resolve({
    list: responseData.data,
    total: responseData.pagination.total
  })
}
```

### 5.3 性能优化

- 使用并发请求（`Promise.allSettled`）
- 添加容错处理
- 超时错误静默处理

## 六、常见错误处理

### 6.1 Token 过期

**错误**：401 Unauthorized

**处理**：
- 自动调用 refreshToken 接口
- 刷新成功后重试原请求
- 刷新失败则跳转登录页

### 6.2 数据为空

**检查步骤**：
1. 查看控制台日志，确认接口是否调用成功
2. 查看返回的数据格式
3. 确认 `request.js` 是否正确解析
4. 确认页面是否正确使用数据

### 6.3 网络超时

**处理**：
- 检查后端服务是否启动
- 检查 baseURL 配置
- 使用并发加载提升性能
