# 第2章 系统分析

## 2.1 可行性分析

### 2.1.1 经济可行性分析

文栈博客系统采用完全开源的技术栈，前端 Vue 3、Vite、Naive UI、Pinia，后端 Express、MySQL、jsonwebtoken、bcrypt 均免费开源，无需支付软件授权费用。服务器方面，Node.js 服务内存占用小，单核 1GB 内存云服务器即可运行，前端静态文件可托管于低成本 CDN。整体开发与运维成本较低，经济可行性良好。

### 2.1.2 技术可行性分析

Vue 3 引入 Composition API 与 Proxy 响应式系统，性能优越，已被大量企业采用；Vite 基于原生 ES Module，构建速度快；Express 是 Node.js 最成熟的 Web 框架；MySQL 稳定性与性能经大量生产环境验证；JWT、bcrypt 均为业界标准安全方案。所有技术成熟可靠，技术可行性高。

### 2.1.3 操作可行性分析

前台界面以文章阅读为核心，布局清晰，普通用户无需培训即可使用。后台采用侧边栏导航，功能分类明确。WangEditor 富文本编辑器提供接近 Word 的编辑体验，学习成本低。部署方面，`npm start` 启动后端，前端构建产物直接托管，SQL 脚本一键初始化数据库，操作可行性高。

## 2.2 需求分析

### 2.2.1 关键技术

**Vue 3**：核心前端框架，Composition API 提升逻辑复用性，`<script setup>` 简化书写，Proxy 响应式性能更优。

**Pinia**：Vue 3 官方推荐状态管理库，管理 token、用户信息、系统配置等全局状态，API 简洁轻量。

**RESTful API**：以资源为核心，通过 HTTP 方法（GET/POST/PUT/DELETE）表达操作，统一响应格式 `{ code, message, data }`。

**JWT 认证**：服务端签发 token（2小时）与 refreshToken（7天），前端 Axios 拦截器自动刷新，实现无感登录，服务端无需存储 Session。

**bcrypt 加密**：内置随机盐的密码哈希函数，saltRounds=10，有效抵御彩虹表攻击与暴力破解。

**时间戳防重放**：前端每次请求携带 `X-Request-Time` 毫秒时间戳，后端校验与服务器时间差不超过 30 秒，超时拒绝请求。

**ECharts**：百度开源图表库，用于展示用户增长、文章发布、流量来源等运营数据的可视化。

**Multer**：Express 文件上传中间件，处理头像、封面、富文本图片等上传，存储至 `public/upload/`。

### 2.2.2 业务流程分析

**用户注册登录流程**：用户填写账号、密码、邮箱及图形验证码提交注册，后端校验后 bcrypt 加密密码存入数据库。登录时校验通过后签发 token 与 refreshToken，前端存入 localStorage 完成登录。

**文章发布流程**：管理员或编辑在后台填写标题、摘要、封面、分类、标签，使用 WangEditor 编写内容，提交后后端校验权限写入数据库，支持正常、置顶、回收站三种状态。

**评论审核流程**：用户提交评论，后端进行敏感词过滤（替换为 ***）后以待审核状态存库。管理员审核通过后评论在前台展示，形成内容安全闭环。

**Token 刷新流程**：前端检测到 401 时自动用 refreshToken 换取新 token 并重发原请求；若 refreshToken 也过期则跳转登录页。

### 2.2.3 功能需求分析

系统功能划分为六大模块，各模块需求如下：

| 模块 | 主要功能需求 |
|------|-------------|
| 用户认证 | 注册（验证码+密码强度）、登录（JWT）、找回密码（邮箱验证）、用户信息修改、Token 自动刷新、用户管理 |
| 文章管理 | 富文本 CRUD、状态管理（正常/置顶/回收站）、分页搜索、分类/标签/时间归档筛选、阅读量统计、排行榜 |
| 评论系统 | 发表评论、楼中楼回复、敏感词过滤、人工审核、批量管理 |
| 分类标签 | 分类增删改查、标签增删改查（自动去重）、多维度归档筛选 |
| 系统设置 | 站点名称/描述/LOGO、主题切换、页脚配置、敏感词库、轮播图管理（仅管理员）|
| 数据看板 | 用户增长趋势、文章发布统计、热门文章排行、流量来源统计、平台数据概览（管理员/编辑）|

### 2.2.4 非功能性需求分析

**性能需求**：正常负载下接口平均响应时间 < 500ms，支持 100+ 并发用户，数据库列表查询 < 200ms。

**安全性需求**：密码 bcrypt 加密存储；接口 JWT 鉴权；参数化查询防 SQL 注入；内容 XSS 转义；时间戳防重放。

**可维护性需求**：代码按路由/控制器/服务/数据库四层组织；Swagger 自动生成 API 文档；关键函数有注释说明。

**可扩展性需求**：RESTful 接口规范，便于扩展；Vue 组件化开发，新模块可独立集成；数据库表预留扩展字段。

### 2.2.5 数据需求分析

系统需持久化存储以下核心数据：

- **用户数据**：账号、密码（加密）、昵称、头像、邮箱、角色（admin/editor/user）、积分、注册时间、最后登录时间
- **文章数据**：标题、摘要、封面、内容（HTML）、状态、分类ID、阅读量（站内/站外）、点赞数、收藏数、作者ID、发布时间
- **评论数据**：文章ID、内容、父评论ID、用户ID、审核状态、发表时间
- **分类/标签数据**：名称、描述；文章与标签多对多关联
- **互动数据**：点赞记录（用户ID+文章ID）、收藏记录（用户ID+文章ID）
- **积分数据**：积分流水（用户ID、金额、类型、描述）、积分商品、积分订单
- **系统数据**：站点配置（名称/描述/LOGO/主题/页脚/敏感词）、轮播图、友情链接、留言

### 2.2.6 接口需求分析

系统后端提供 RESTful 风格接口，主要接口分组如下：

| 接口分组 | 路径前缀 | 说明 |
|---------|---------|------|
| 用户接口 | /users | 注册、登录、刷新Token、用户CRUD、找回密码 |
| 文章接口 | /articles | 文章CRUD、归档、排行榜、阅读量 |
| 分类接口 | /categories | 分类CRUD |
| 标签接口 | /tags | 标签CRUD |
| 评论接口 | /comments | 评论CRUD、审核 |
| 点赞接口 | /likes | 点赞/取消点赞 |
| 收藏接口 | /favorites | 收藏/取消收藏 |
| 留言接口 | /messages | 留言CRUD |
| 积分接口 | /points | 积分商品、兑换订单、积分流水 |
| 看板接口 | /dashboard | 统计数据查询 |
| 设置接口 | /otherswitch | 系统配置读写 |
| 上传接口 | /upload | 图片文件上传 |
| 友链接口 | /friendslink | 友情链接CRUD |

需登录的接口路径含 `/token`，通过 JWT 中间件统一鉴权；公开接口无需携带 token。系统提供 Swagger UI（/api-docs）供接口文档查阅与调试。

### 2.2.7 将来可能提出的需求分析

随着系统使用规模的扩大，未来可能提出以下需求：

**多级分类**：当前分类为扁平结构，当文章数量增多时，用户可能需要多级分类（如一级分类/二级分类）以实现更精细的内容组织。

**全文检索引擎**：当前基于 MySQL LIKE 的模糊查询在数据量大时性能下降，未来可引入 Elasticsearch 实现高性能全文检索。

**消息通知**：用户评论被回复、文章被点赞收藏时，可通过站内信或邮件通知相关用户，提升互动体验。

**移动端适配**：随着移动端流量占比提升，未来可开发响应式移动端页面或独立小程序，覆盖更多用户场景。

**内容推荐**：基于用户阅读历史和文章标签，引入协同过滤或内容推荐算法，为用户提供个性化文章推荐。
