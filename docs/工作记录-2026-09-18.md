## 三、关键技术结论与坑（重要，供后续开发参考）

1. **Vue 3 响应式陷阱（打字机 bug 根因）**：普通对象 push 进 `ref([])` 后，闭包里改原始对象**不触发视图更新**，流式内容只在结束时一次性出现。修复：`const reply = reactive({...})` 后再 push，闭包持有代理。流式上屏用"缓冲区 + 24ms 定时器匀速吐字（积压越多吐越快）"实现打字机。
2. **Node 的 `req.on('close')` 在请求体读完时就触发**（非客户端断开），SSE 场景会瞬间 abort 掉大模型请求；必须监听 `res.on('close')`。
3. **智谱免费模型限流按模型独立计**：错误码 1302 = 触发速率限制；`glm-4.7-flash` 被限时表现为流式请求挂起（非立刻 429），`glm-4-flash-250414` 稳定（~200ms 首包，现为默认），`glm-4.5-flash` 是推理模型延迟高。换模型改 `aiConfig.js` 的 `model` 一行。
4. **Windows 下 curl 发中文 JSON 是 GBK 字节**，服务端按 UTF-8 解析成乱码导致模型答非所问——测试中文接口用 Node/浏览器客户端（`test-ai-guide.js` 即为此写）。
5. **vite 在含中文的路径下偶尔漏文件变更事件**：改了代码但页面不更新时，先重启 `npm run dev`。
6. 免费模型有并发数限制；个人博客场景实测打字机 <1s 完成，够用。
