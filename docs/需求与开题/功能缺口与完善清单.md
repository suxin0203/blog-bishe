# 文栈博客 · 开题功能缺口与完善清单

根据开题报告中的**六大核心模块**、**论文与文档要求**和**非功能要求**，与当前代码库（Express + Vue3）对照后的结论如下。清单按「已实现 / 需完善 / 缺失 / 大改动」分类，便于后续逐个完成；**必须完成的核心基础功能**会单独标出。

---

## 一、用户认证模块

| 子项 | 状态 | 说明 |
|------|------|------|
| 用户注册 | 需完善 | 已有注册（用户名+密码+邮箱格式校验）。**缺：邮箱验证**（验证码或邮件链接）；**缺：密码强度校验**（仅 6～18 位，无数字/字母/特殊字符等规则）。 |
| 用户登录 | 已实现 | 用户名+密码，JWT 签发，返回 token + 用户信息。 |
| 用户登出 | 已实现 | 前端清除 token 与 userInfo 并刷新。 |
| **Token 自动刷新（无感登录）** | **缺失** | 当前无 refreshToken 机制；401 时直接清 token 并提示重新登录。开题要求「支持 Token 自动刷新」。 |
| 密码加密存储 | 已实现 | bcrypt 存储，登录时 compare。 |

**涉及文件（参考）：**  
- 注册/登录逻辑：`Express/controllers/userController.js`、`Vue3/src/views/Login.vue`  
- 请求与 401 处理：`Vue3/src/api/request.js`

**大改动说明：**
- **邮箱验证**：需引入邮件发送（如 nodemailer）+ 验证码或链接表/缓存，前后端都要加流程，改动中等偏大。
- **Token 自动刷新**：需后端签发 refreshToken（及 refresh 接口）、前端在 401 时先尝试 refresh 再重发原请求，并统一在 axios 响应拦截里处理，改动中等。

## 四、分类与标签模块

| 子项 | 状态 | 说明 |
|------|------|------|
| **多级分类管理** | **缺失** | 开题要求「多级分类」。当前分类为扁平结构（wz_categories 无 parent_id），无父子层级。 |
| 标签自由添加 | 已实现 | 后台可增删改标签；文章侧有 findOrCreateByName 用于关联时去重。 |
| 标签自动去重 | 需完善 | 文章编辑时通过 findOrCreateByName 可避免重复名称；**后台「标签管理」里单独新增标签时，后端未做同名检查**，可能产生重名。 |
| 按分类、标签归档 | 已实现 | 文章列表支持按 category_id、tag_id 筛选。 |
| **按时间归档** | **缺失** | 开题要求「按时间归档查看文章」。当前无按年/月等时间维度的归档页或接口（如「2024 年 3 月」列表）。 |

**涉及文件：** `Express/services/categoryService.js`、`Express/services/tagService.js`、分类/标签前后台页面。

**大改动说明：**
- **多级分类**：需在 wz_categories 增加 parent_id（或 path/level），前后台分类树展示与选择、文章归属逻辑都要改，**改动大**。
- **按时间归档**：可新增「归档」页与接口（按 created_at 年/月聚合），前端增加归档入口与列表，**改动中等**。

## 十、角色与功能梳理（各角色应有能力）

| 角色 | 前台能力 | 后台能力 | 备注 |
|------|----------|----------|------|
| **管理员 (is_root=1)** | 与普通用户相同；可进入后台 | 全部：用户/文章/分类/标签/评论/留言/友链/积分商城与订单/系统设置/数据看板 | 无缺失。 |
| **编辑 (role=editor)** | 与普通用户相同；可进入后台 | 内容与互动：文章/分类/标签/评论/留言/友链；积分商城（商品与订单）；无用户管理、系统设置 | 无缺失。 |
| **普通用户 (role=user)** | 浏览文章、评论、点赞、收藏、留言；积分商城兑换；兑换记录（/my-orders）；积分记录（/my-points-log）；头像下拉：编辑资料、兑换记录、积分记录、退出 | 无（不可进入 dashboard） | 兑换记录与积分记录已从头像菜单进入。 |

**补充说明：** 后端 `GET /points/orders?my=1` 未登录时 401；`GET /points/log` 未登录 401，普通用户仅能查本人流水，管理员/编辑可传 `userId` 查他人。
