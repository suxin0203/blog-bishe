# 文栈博客系统的设计与实现 · 项目说明文档

## 1. 项目名称与项目简介

**项目名称：** 文栈博客系统（Wenzhan Blog）

**项目简介：** 文栈博客是一套前后端分离的轻量级博客系统，采用 Vue 3 + Express + MySQL 技术栈，实现了用户认证、文章管理、评论互动、分类标签、系统设置、数据看板等功能模块，支持 JWT 无状态认证、Token 自动刷新、时间戳防重放、角色权限控制等特性，为个人或团队提供内容发布、管理与运营可视化的完整解决方案。

---

## 2. 开发目的与应用场景

**开发目的：**
- 满足个人与团队对博客平台在权限划分、数据可视化、用户互动闭环等方面的需求
- 提升内容发布、管理与互动的整体效率与用户体验
- 为轻量级博客系统的设计与实现提供可参考的技术方案

**应用场景：**
- 个人技术博客、知识分享平台
- 团队内容管理与协作发布（管理员、编辑、普通用户三级权限）
- 小型社区或组织的内容运营与数据分析

- **运行环境：** Node.js（≥ 14.17.0）

### 运行环境

## 5. 系统架构与流程

### 前后端分离架构
```
┌─────────────┐         HTTP/HTTPS (RESTful API)         ┌─────────────┐
│   Vue 3     │ ────────────────────────────────────────> │   Express   │
│  (前端 UI)   │ <──────────────────────────────────────── │  (后端 API)  │
└─────────────┘         JSON 数据交互                      └─────────────┘
                                                                  │
                                                                  │ mysql2
                                                                  ▼
                                                           ┌─────────────┐
                                                           │    MySQL    │
                                                           │  (数据持久化) │
                                                           └─────────────┘
```

### 请求处理流程

**前端请求流程：**
1. 用户操作触发事件（点击、提交表单等）
2. Vue 组件调用 API 模块（`src/api/*.js`）
3. Axios 请求拦截器：
   - 添加时间戳请求头 `X-Request-Time`（防重放）
   - 需登录接口自动添加 `Authorization: Bearer <token>`
4. 发送 HTTP 请求到后端
5. Axios 响应拦截器：
   - 业务 401 时自动调用 `/users/refresh` 刷新 Token
   - 刷新成功后重发原请求，失败则清除 Token 并跳转登录
6. 组件接收响应数据并更新 UI

**后端处理流程：**
1. Express 接收请求
2. 全局中间件：
   - CORS 跨域处理
   - 时间戳防重放校验（`X-Request-Time` 与服务器时间差 ≤ 30 秒）
   - Multer 文件上传处理
3. 路由匹配（`routes/*.js`）
4. JWT 认证中间件：
   - `/token` 路径需强制登录，校验 Token 并解析用户信息
   - 角色权限校验（管理员 / 编辑 / 普通用户）
5. 控制器（`controllers/*.js`）调用服务层（`services/*.js`）
6. 服务层执行业务逻辑并操作数据库（mysql2）
7. 返回统一格式 JSON 响应：`{ code, message, data }`

**数据库存储流程：**
1. 服务层通过 mysql2 连接池执行 SQL 查询
2. 增删改查操作：
   - 用户密码通过 bcrypt 加密存储
   - 文章内容、评论内容存储为 TEXT 类型
   - 敏感词过滤后再入库
3. 事务处理（如积分扣减 + 订单创建）
4. 返回查询结果或影响行数

## 6. 核心功能实现思路

### 6.1 登录认证与 Token 自动刷新

**实现思路：**
1. **登录流程：**
   - 用户提交账号密码（前端 Base64 编码传输）
   - 后端 bcrypt 校验密码，通过后签发 `token`（有效期 2 小时）和 `refreshToken`（有效期 7 天）
   - 前端存储 `token` 和 `refreshToken` 到 localStorage，并写入 Pinia 状态
   - 每日首次登录赠送 5 积分

2. **Token 自动刷新：**
   - 前端 Axios 响应拦截器捕获业务 401
   - 自动调用 `POST /users/refresh` 接口，传入 `refreshToken`
   - 后端校验 `refreshToken` 有效性，签发新 `token`
   - 前端更新 localStorage 和 Pinia，重发原请求
   - 若 `refreshToken` 也过期，清除本地状态并跳转登录

3. **时间戳防重放：**
   - 前端每次请求添加 `X-Request-Time` 请求头（当前时间戳毫秒）
   - 后端校验与服务器时间差 ≤ 30 秒，超时拒绝请求

**关键代码位置：**
- 前端：`Vue3/src/api/request.js`（Axios 拦截器）
- 后端：`Express/controllers/userController.js`（登录、刷新）、`Express/app.js`（时间戳中间件、JWT 中间件）

---

### 6.2 文章发布与富文本编辑

**实现思路：**
1. **富文本编辑器：**
   - 前端集成 WangEditor，支持标题、段落、列表、代码块、图片、链接等
   - 图片上传通过 `POST /upload/JPG` 接口，后端 Multer 处理并返回 URL
   - 编辑器内容以 HTML 格式存储到数据库 `content` 字段

2. **文章创建流程：**
   - 用户填写标题、摘要、封面、分类、标签、内容
   - 提交 `POST /articles/token`，后端校验权限（管理员 / 编辑）
   - 插入 `wz_articles` 表，关联分类（`category_id`）
   - 标签通过 `findOrCreateByName` 去重后插入 `wz_article_tags` 关联表
   - 返回新文章 ID

3. **文章编辑与状态管理：**
   - 编辑通过 `PUT /articles/token/:id` 更新
   - 状态字段 `status`：0 正常、1 置顶、2 回收站
   - 回收站文章可恢复或永久删除

**关键代码位置：**
- 前端：`Vue3/src/views/dashboard/Article.vue`（文章编辑页）
- 后端：`Express/controllers/articleController.js`、`Express/services/articleService.js`

---

### 6.3 分页查询与搜索筛选

**实现思路：**
1. **分页参数：**
   - 前端传递 `page`（页码）、`pageSize`（每页条数）
   - 后端计算 `LIMIT` 和 `OFFSET`：`LIMIT pageSize OFFSET (page - 1) * pageSize`

2. **搜索与筛选：**
   - 关键词搜索：`WHERE (title LIKE '%keyword%' OR summary LIKE '%keyword%' OR content LIKE '%keyword%')`
   - 分类筛选：`WHERE category_id = ?`
   - 标签筛选：`JOIN wz_article_tags WHERE tag_id = ?`
   - 时间归档：`WHERE YEAR(created_at) = ? AND MONTH(created_at) = ?`
   - 状态筛选：`WHERE status = ?`

3. **排序规则：**
   - 置顶优先：`ORDER BY status DESC`（status=1 置顶排最前）
   - 按 ID 降序：`ORDER BY id DESC`（最新文章在前）

4. **返回数据：**
   - `list`：当前页文章列表
   - `pagination`：`{ page, pageSize, total, totalPages }`

**关键代码位置：**
- 后端：`Express/services/articleService.js`（`getList` 方法）

---

### 6.4 权限控制与角色管理

**实现思路：**
1. **角色定义：**
   - `is_root=1`：管理员（超级权限）
   - `role='editor'`：编辑（内容管理权限）
   - `role='user'`：普通用户（前台互动权限）

2. **后端权限校验：**
   - `/token` 路径需强制登录，JWT 中间件解析 `req.user`
   - 管理员与编辑可访问所有后台接口
   - 普通用户仅可访问：
     - 点赞 / 收藏接口（`/likes/token`、`/favorites/token`）
     - 修改自己的用户信息（`PUT /users/token/:id`，校验 `req.user.id === :id`）
   - 其他后台接口返回 403

3. **前端权限控制：**
   - Pinia 存储用户信息（`is_root`、`role`）
   - 路由守卫：非管理员 / 编辑访问 `/dashboard` 时跳转首页
   - 菜单与按钮根据角色动态显示 / 隐藏

4. **编辑权限限制：**
   - 编辑仅能管理自己创建的文章（`author_id = req.user.id`）
   - 无用户管理、系统设置权限

**关键代码位置：**
- 后端：`Express/app.js`（JWT 中间件权限校验）
- 前端：`Vue3/src/common/router.js`（路由守卫）、`Vue3/src/stores/AdminStore.js`（权限状态）

---

### 6.5 评论敏感词过滤与审核

**实现思路：**
1. **敏感词配置：**
   - 管理员在系统设置中配置敏感词（逗号分隔），存储到 `wz_otherswitch` 表 `sensitive_words` 字段
   - 后端读取配置并缓存

2. **敏感词过滤：**
   - 用户提交评论时，后端从配置中读取敏感词列表
   - 遍历敏感词，使用正则替换为 `***`：`content.replace(new RegExp(word, 'gi'), '***')`
   - 过滤后的内容存入数据库

3. **人工审核：**
   - 评论状态 `status`：0 待审核、1 通过、2 屏蔽
   - 新评论默认 `status=0`，需管理员 / 编辑审核后才在前台显示
   - 后台评论管理页可批量审核 / 屏蔽 / 删除

4. **前台展示：**
   - 文章详情页仅显示 `status=1` 的评论
   - 支持楼中楼回复（`parent_id` 关联）

**关键代码位置：**
- 后端：`Express/controllers/commentController.js`（敏感词过滤逻辑）、`Express/services/commentService.js`
