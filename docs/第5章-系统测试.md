# 第5章 系统测试

## 5.1 测试计划

### 5.1.1 测试范围与主要内容

本次测试覆盖文栈博客系统的全部功能模块，主要测试内容包括：

- 用户认证功能：注册、登录、Token 刷新、找回密码
- 文章管理功能：文章发布、编辑、删除、分页查询、搜索筛选、时间归档
- 评论系统功能：评论发表、敏感词过滤、楼中楼回复、审核管理
- 权限控制功能：三级角色权限校验、接口鉴权、前端路由守卫
- 数据看板功能：统计数据准确性、ECharts 图表渲染
- 非功能测试：接口响应性能、安全性（时间戳防重放、SQL注入防护）

### 5.1.2 测试方法

本次测试采用以下方法：

**黑盒测试**：以用户视角测试系统功能，不关注内部实现，通过输入合法/非法数据验证系统输出是否符合预期。

**接口测试**：使用 Postman 对后端 REST API 进行逐接口测试，验证请求参数校验、响应格式、业务逻辑、错误处理的正确性。

**边界值测试**：针对分页（page=0、超出总页数）、积分（负数积分）、文章内容（空内容、超长内容）等边界场景进行专项测试。

**安全性测试**：测试 SQL 注入、XSS 攻击、时间戳篡改、Token 伪造等安全场景，验证系统防护机制的有效性。

## 5.3 非功能测试

### 5.3.1 性能测试

使用 Postman 对核心接口进行多次请求，记录响应时间如下：

| 接口 | 平均响应时间 | 最大响应时间 | 是否满足要求（<500ms）|
|------|------------|------------|--------------------|
| GET /articles（首页列表） | 85ms | 142ms | ✅ |
| GET /articles/:id（文章详情） | 62ms | 98ms | ✅ |
| POST /users/login（登录） | 210ms | 280ms | ✅ |
| GET /dashboard/stats（看板） | 320ms | 450ms | ✅ |
| POST /comments（发表评论） | 75ms | 110ms | ✅ |

所有核心接口平均响应时间均低于 500ms，满足性能需求。看板接口因涉及多表聚合查询响应时间相对较长，但仍在可接受范围内。

### 5.3.2 安全测试

| 测试项 | 测试方式 | 测试结果 |
|--------|---------|--------|
| SQL 注入 | 在搜索参数中注入 SQL 语句（如 `' OR 1=1 --`） | 参数化查询有效防护，返回空结果而非全部数据 |
| XSS 攻击 | 在评论内容中注入 `<script>alert(1)</script>` | 前端渲染时转义，未执行脚本 |
| Token 伪造 | 使用错误密钥签名的 token 访问鉴权接口 | 返回 401，校验失败 |
| Token 过期 | 使用过期 token 请求 | 返回 401，前端自动刷新 |
| 时间戳重放 | 发送 X-Request-Time 偏差 60s 的请求 | 返回「请求已过期」，拒绝处理 |
| 密码明文传输 | 抓包分析注册/登录请求 | 密码为 Base64 编码，数据库存储为 bcrypt 哈希 |
| 未授权访问 | 无 token 访问 /token 接口 | 返回 401，拒绝访问 |

所有安全测试项均通过，系统安全防护机制有效。

## 5.4 测试结论

经过功能测试、性能测试、安全测试，文栈博客系统的测试结论如下：

1. **功能完整性**：全部 34 个功能测试用例均通过，系统各功能模块运行正常，业务逻辑正确，边界情况处理合理。

2. **性能表现**：核心接口平均响应时间均低于 500ms，文章列表、文章详情等高频接口响应时间在 100ms 以内，性能表现良好，满足设计需求。

3. **安全性**：SQL 注入防护、XSS 防护、Token 鉴权、时间戳防重放、密码加密存储等安全机制全部有效，系统具备良好的安全防护能力。

4. **存在的不足**：数据看板统计接口在数据量较大时响应时间可能进一步增加，后续可通过数据缓存（Redis）或定时聚合任务进行优化；敏感词过滤基于简单正则匹配，面对变体敏感词（如拼音、谐音）的识别能力有限，可引入更完善的敏感词库或 NLP 模型进行优化。
