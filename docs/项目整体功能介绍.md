# 文栈博客系统整体功能介绍

> 本文档对文栈博客系统进行整体功能整合说明，面向项目展示、毕业设计答辩、功能验收和后续开发维护。它综合了 `项目说明文档.md`、`功能模块.md`、`系统核心技术.md`、`积分系统说明.md` 与 `PC扫码微信小程序登录设计.md` 的核心内容。

---

## 一、项目总体定位

文栈博客系统是一套基于 `Vue 3 + Express + MySQL` 的前后端分离内容管理与博客展示平台。系统不仅支持传统博客的文章发布、分类标签、评论互动等基础能力，还扩展了用户权限、积分激励、运营看板、微信登录、PC 扫微信小程序码登录等功能。

系统定位可以概括为：

```text
内容发布平台 + 用户互动平台 + 后台管理平台 + 积分运营平台 + 跨端登录实践平台
```

与普通博客项目相比，本系统更强调工程完整性和业务扩展性，适合用于个人博客、课程设计、毕业设计、项目展示或小型内容平台原型。

## 二、系统核心价值

### 2.1 对普通用户

- 可以浏览文章、查看分类和标签。
- 可以注册、登录并维护个人信息。
- 可以评论、点赞、收藏文章。

- 可以查看积分并参与积分兑换。

### 2.2 对编辑和管理员

- 可以发布、编辑、删除和恢复文章。
- 可以维护分类、标签、轮播图、友情链接等内容资源。
- 可以审核评论和留言。
- 可以管理用户、查看运营数据。
- 可以维护积分商品和处理兑换订单。

### 2.3 对项目展示

- 能展示完整的前后端分离架构。
- 能展示 JWT 鉴权、RBAC 权限、refreshToken 等认证机制。
- 能展示积分系统、扫码登录、数据看板等差异化功能。
- 能支撑 Web 端与微信小程序端扩展规划。

## 三、系统技术架构

### 3.1 前端架构

前端位于 `Vue3/` 目录，采用 Vue 3 + Vite 构建。

核心技术包括：

| 技术 | 用途 |
|------|------|
| Vue 3 | 页面组件与响应式开发 |
| Vite | 前端构建工具 |
| Naive UI | 后台与前台 UI 组件 |
| Vue Router | 路由管理 |
| Pinia | 状态管理 |
| Axios | HTTP 请求封装 |
| WangEditor | 富文本编辑器 |
| ECharts | 数据看板图表 |
| Prism.js | 代码高亮 |
| CryptoJS | 前端加密与编码辅助 |

### 3.2 后端架构

后端位于 `Express/` 目录，采用 Express 分层结构。

核心分层如下：

| 层级 | 目录 | 作用 |
|------|------|------|
| 路由层 | `routes/` | 定义接口路径和请求方法 |
| 控制器层 | `controllers/` | 接收请求、校验参数、组织响应 |
| 服务层 | `services/` | 封装业务逻辑 |
| 公共层 | `common/` | 数据库连接、响应格式、工具函数 |
| 配置层 | `config/` | Swagger 等工程配置 |

### 3.3 数据库

数据库采用 MySQL，主要用于存储：

- 用户信息
- 文章内容
- 分类标签
- 评论留言
- 点赞收藏关系
- 积分流水
- 积分商品和订单
- 扫码登录会话
- 系统配置

### 3.4 请求链路

```text
用户操作
→ Vue 组件触发事件
→ 调用 API 封装方法
→ Axios 拦截器附加 Token 和时间戳
→ Express 路由接收请求
→ JWT 鉴权与角色判断
→ Controller 调用 Service
→ MySQL 查询/写入
→ 返回统一 JSON 响应
→ 前端更新页面状态
```

## 五、主要业务模块说明

## 5.1 用户认证与权限模块

该模块是系统身份基础，负责所有用户入口与访问控制。

核心能力：

- 图形验证码。
- 用户注册与登录。
- JWT accessToken 签发。
- refreshToken 刷新机制。
- 当前用户信息获取。
- 找回密码与修改密码。
- 管理员新增用户。
- 用户列表、编辑、删除。

权限角色：

| 角色 | 权限说明 |
|------|----------|
| 游客 | 浏览公开文章、分类、标签、轮播、友链、评论列表 |
| 普通用户 | 游客能力 + 评论、点赞、收藏、积分流水、个人资料修改 |
| 编辑 | 普通用户能力 + 内容管理、评论管理、部分后台能力 |
| 管理员 | 系统最高权限，管理所有模块 |

## 5.2 文章内容模块

文章模块是系统核心业务模块。

核心能力：

- 前台文章列表。
- 文章详情。
- 热门文章排行。
- 文章归档。
- 后台文章列表。
- 新增、编辑、删除、恢复文章。
- 阅读量统计。
- 分类和标签关联。
- 富文本图片上传。

典型流程：

```text
编辑/管理员登录后台
→ 进入文章管理
→ 填写标题、摘要、正文、分类、标签
→ 上传封面或正文图片
→ 保存文章
→ 前台文章列表展示
→ 用户进入详情页阅读
→ 阅读量增加
```

## 5.4 评论、点赞、收藏与留言模块

这些模块构成用户互动体系。

### 评论系统

- 用户可在文章详情页发表评论。
- 评论可进入审核流程。
- 后台可修改状态或删除评论。
- 评论审核通过后可触发积分奖励。

### 点赞系统

- 登录用户可点赞或取消点赞文章。
- 被点赞文章作者获得积分。
- 自己点赞自己的文章不产生积分。

### 收藏系统

- 登录用户可收藏文章。
- 可在个人中心查看我的收藏。
- 支持取消收藏。

### 留言模块

- 用于站点留言板场景。
- 支持前台留言和后台管理。

## 5.5 积分系统与积分商城

积分系统是文栈博客的特色模块之一，用于提升用户活跃度。

### 积分来源

| 场景 | 积分 | 限制 |
|------|------|------|
| 每日登录 | +5 | 每日一次 |
| 发布文章 | +10 | 每日最多 100 |
| 评论审核通过 | +5 | 每日最多 50 |
| 文章被点赞 | +1 | 自己点赞无效 |
| 取消点赞 | -1 | 回退作者获赞积分 |
| 删除文章 | 扣回发布奖励 | 如果曾获得发布积分 |
| 删除已通过评论 | 扣回评论奖励 | 如果曾获得评论积分 |
| 积分兑换商品 | 扣除商品积分 | 积分不足不可兑换 |
| 管理员调整 | 可正可负 | 后台人工调整 |

### 积分商城

积分商城支持：

- 商品列表。
- 商品详情。
- 商品新增、编辑、删除。
- 用户兑换商品。
- 后台处理订单。
- 积分流水查询。

### 积分系统特点

- 采用“用户当前积分 + 积分流水”的实现方式。
- 每次积分变化都尽量记录流水。
- 支持每日上限和积分回退。
- 积分 reason 可解析为用户友好的文案。

## 5.7 微信登录与 PC 扫码登录模块

该模块是系统跨端能力的核心亮点。

### 基础微信能力

- 通过微信 code 换取 openid。
- 根据 openid 查询已绑定系统用户。

### PC 扫小程序码登录

典型流程：

```text
PC 登录页创建扫码会话
→ 后端生成 sceneId 和小程序码
→ 用户使用微信小程序扫码
→ 小程序通过 wx.login 获取 code
→ 后端获取 openid 并判断绑定状态
→ 已绑定则确认登录
→ 未绑定则注册或绑定已有账号
→ PC 端轮询到 confirmed 状态
→ 获取 token 和 refreshToken
→ 完成 Web 登录
```

状态包括：

- `pending`：待扫码或待确认。
- `confirmed`：已确认，PC 可领取登录态。
- `completed`：PC 已消费登录结果。
- `expired`：会话已过期。

该功能展示了 Web、后端、小程序三端协同能力。

## 六、系统安全机制

### 6.1 密码安全

- 前端进行基础编码。
- 后端使用 bcrypt 哈希存储密码。
- 登录时通过 bcrypt compare 校验。

### 6.2 Token 认证

- 登录成功后签发 accessToken 和 refreshToken。
- 受保护接口通过 `Authorization: Bearer <token>` 访问。
- Token 过期后可通过 refreshToken 刷新。

### 6.3 RBAC 权限控制

后端在 `Express/app.js` 中统一拦截包含 `/token` 的接口，并根据角色判断权限。

普通用户只允许访问：

- 点赞接口。
- 收藏接口。
- 自己的积分流水。
- 修改本人资料。

管理员和编辑可访问后台管理接口。

### 6.4 时间戳防重放

前端请求可携带 `X-Request-Time` 请求头。

后端判断客户端时间与服务器时间差，如果超过 30 秒则拒绝请求。

### 6.5 数据访问安全

- 使用 mysql2 参数化查询。
- 避免拼接 SQL。
- 对关键输入做字段校验和白名单控制。

### 6.6 内容安全

- 评论审核后展示。
- 支持敏感词处理。
- 富文本发布权限限制在后台角色。
- 上传资源统一由后端处理。
