# AI 向导 · 技术报告（面试问答版）

> 项目：文栈博客 AI 向导（基于个人博客的站内 AI 助手）
> 技术栈：Vue3 + Express + MySQL + 智谱 GLM（OpenAI 兼容协议）
> 面向场景：技术面试中介绍本项目时的完整逻辑讲稿与追问应对

---

## 一、30 秒版本（开场介绍）

我在自己的博客系统里做了一个站内 AI 向导：访客在任意页面点右下角悬浮球，就能用自然语言查询站点内容——"有哪些关于 Nginx 的文章""这篇文章讲了什么""站点一共有多少文章"。底层基于智谱 GLM 大模型，通过 **Function Calling（工具调用）** 让模型自主查询 MySQL 真实数据后组织回答，回答中自动附带文章链接。前端用 SSE 流式输出实现打字机效果，配套步骤时间线展示执行进度。

架构一句话：**Vue3 悬浮球组件 → Express SSE 接口 → 工具注册表 → MySQL 真实数据 → 流式回答**。

## 二、核心流程走读

### 2.1 一次提问的完整链路

```
用户提问
  → POST /ai/chat/stream（SSE）
  → 控制器五道前置：API Key / IP限流(10次/分) / 参数校验 / 会话定位 / 响应头
  → 轮1 非流式（带 6 个工具定义）
      ├─ 模型直接回答 → SSE 下发全文（前端打字机渲染）
      └─ 模型点名工具（如 search_articles{keyword:"nginx"}）
          → 执行工具查 MySQL → 结果回填消息 → 轮2 流式生成最终回答
  → 会话与消息落库（wz_ai_sessions / wz_ai_messages）
  → data:[DONE]
```

### 2.2 六个工具（注册表模式）

| 工具 | 职责 |
|------|------|
| search_articles | 按关键词/分类/标签搜索文章（附正文摘录与链接） |
| list_categories / list_tags | 分类、标签及计数 |
| get_hot_articles | 阅读/点赞/收藏排行 |
| get_article_detail | 按 id 读正文摘录（800 字） |
| get_site_overview | 站点统计 |

设计要点：schema 与 handler 分离；handler 复用现有 service 层函数；永不 throw（错误以 `{ok:false}` 返回给模型自行解释）；结果强制截断防上下文爆炸。

### 2.3 双格式渲染

文章正文存 HTML（富文本编辑器产出），AI 回复是 Markdown——两条链路独立：正文 `v-html` 直出 + CSS 约束；AI 回复 markdown-it 渲染 + DOMPurify 消毒。互不干扰，也避免了"为了统一而统一"的改造风险。

## 三、关键设计决策（面试追问高发区）

### Q1：为什么用 Tool Calling 而不是 RAG / 向量数据库？

**答**：按数据形态分流。站点数据是结构化的（文章标题/分类/标签在 MySQL），Tool Calling 让模型生成 SQL 参数查真实数据，回答**零幻觉**且附真实链接。RAG 解决的是"非结构化文本的语义检索"，当前 62 篇文章的规模下，引入向量数据库是过度设计——真要做也是"RAG-lite"：embedding 后内存余弦检索即可。**取舍论证**：规模不到、收益不明确、运维成本确定的方案，先不做；升级路径已预留（正文向量化 + 语义检索工具注册进同一张表即可）。

### Q2：为什么轮 1 用非流式、轮 2 才流式？

**答**：流式解析 tool_calls 的增量拼装复杂度高，而轮 1 需要完整的工具调用决策。折中：轮 1 非流式拿决策（模型思考的 2~5 秒里前端有时间线步骤动画兜底），确认不需要工具的纯聊天也在这一轮直接返回全文（前端打字机匀速播放保证观感），需要工具的才进轮 2 流式。**用一点首字延迟换实现可靠性**，是刻意的工程取舍。

### Q3：为什么 AI 回复的代码块能高亮？用了什么？

markdown-it 的 `highlight` 钩子接 Prism（项目已有依赖），按语言分发 `Prism.highlight`；未命中语言降级为转义文本。渲染结果过 DOMPurify 消毒（白名单 + 链接统一新窗口），防 XSS。

### Q4：会话记忆怎么做的？为什么存库而不是内存？

每次请求从 `wz_ai_messages` 取最近 10 条作为上下文，落库到 `wz_ai_sessions`/`wz_ai_messages` 两张表。相比内存 Map：重启不丢、可回放、可统计（看板的 AI 使用统计卡直接聚合这两张表）。后续多轮工具的消息（role=tool）也在库里，为审计与调试留痕。

## 四、踩坑案例（真实调试记录，比成功经验更值钱）

### 坑 1：Node 14 没有 fetch / AbortController

服务器是宝塔 Node 14，AI 模块初版用原生 `fetch` + `AbortSignal.any`（Node 18/20+ API），线上直接 `ReferenceError`。**修复**：改用 axios（`responseType: 'stream'` + `CancelToken`），中断协议改为普通标记对象 `{cancelled, cancel()}`。**教训**：写代码前先确认运行时版本；兼容层（标记对象）比新语法糖更可移植。

### 坑 2：`undefined` 绑定值导致文章修改接口 500

`articleService.update` 用固定列数组拼 UPDATE，请求缺字段时 `undefined` 进绑定值直接 500。前端表单总是全量提交所以从未暴露——**自动化 CRUD 测试用部分字段请求把它炸了出来**。**修复**：动态字段更新（只 SET 传入的字段）。**教训**：接口要对"部分更新"语义健壮，不能假设调用方总是全量。

### 坑 3：迁移历史数据打破"id 顺序 ≈ 时间顺序"

文章列表原按 `ORDER BY id DESC`（隐含 id 越大越新），批量迁移 40 篇旧文章后假设失效，列表前几页全是旧文章。**修复**：排序显式改 `created_at DESC`。**教训**：自增 id 只做唯一标识，排序语义必须显式用业务时间字段；这类 bug 在补录历史数据后必然出现。

### 坑 4：改密码后 refreshToken 不作废

改密/找回重置只更新了密码哈希，旧设备凭 7 天 refreshToken 仍可续命——"改密码踢不掉盗号者"。**修复**：改密成功后立即作废 `refresh_token`，所有已登录设备强制重新登录。

## 五、安全设计清单

| 机制 | 实现 |
|------|------|
| 一次性验证码 | 算术题 + 5 分钟 TTL + 用后即删 + MD5 比对 |
| 双 token 分级 | access 2h / refresh 7d，改密后 refresh 全作废 |
| 越权拦截 | 编辑角色删 AI 会话 403；无 token 401 |
| 回收站不可见 | 公开详情/AI 工具 `publicOnly`，失效访问控制（OWASP A01）修复 |
| 用户删除安全 | CASCADE 改 RESTRICT + 占位账号换绑，杜绝静默丢内容 |
| AI 防线 | IP 限流 10 次/分、结果截断防上下文爆炸、系统提示词防套取、错误 3 次/日锁定 |
| 密钥管理 | 全部 .env（gitignored），代码零密钥 |

## 六、已知边界与升级路径

| 边界 | 升级路径 |
|------|----------|
| 复合问题最多两轮工具链 | 三期：流式 tool_calls 拼装 |
| 找回密码靠"知识验证"（知道注册邮箱即可改密） | 部署邮件服务（nodemailer + SMTP 授权码）后升级为邮箱重置链接 |
| AI 会话表不清理 | 归档策略（按 updated_at 归档） |
| 内存限流（单进程） | 多实例部署时换 Redis 计数 |
| 回复 Markdown 无代码复制按钮 | 前端小改造 |

## 八、面试快速问答 10 题

1. **为什么不用 LangChain？** 场景是"结构化数据查询 + 单轮工具决策"，直连 API + 自建工具注册表 50 行搞定，引入框架是负资产。框架的价值在复杂编排，我的场景没有。
2. **怎么防 AI 幻觉？** 三层：系统提示词硬约束（数据问题必须调工具）、工具返回真实数据（零编造空间）、搜索结果强制截断附真实链接。
3. **双 token 为什么这么设计？** access 短命（2h）降低泄露影响面，refresh 长命（7d）保体验；改密码即作废全部 refresh，盗号者改密也踢不掉合法用户。
4. **SSE 和 WebSocket 怎么选？** 单向推送 SSE 就够，走 HTTP 无需协议升级；多向交互（语音）才需要 WS。
5. **工具调用的安全边界？** 工具白名单 + 参数 schema 约束 + SQL 全参数化 + 只读查询，模型只能"填参数"不能"写 SQL"。
6. **限流怎么设计的？** AI 接口 IP 级内存限流 10 次/分；找回邮箱验证账号级 3 次/日（挂受害者账户，换 IP 无效）。
7. **回收站为什么公开端点看不到？** 失效访问控制（OWASP A01）修复：`publicOnly` 过滤，公开端点/AI 工具/阅读计数三层全部屏蔽，后台 token 路径不受影响。
8. **删用户为什么文章不丢？** CASCADE 改 RESTRICT + 占位账号换绑：内容是社区资产，不因注销消失，作者显示"已注销用户"。
9. **怎么保证改代码不破坏核心流程？** 分层测试：接口冒烟 22 断言 + 工具单测 14 + 写操作闭环 39 + AI 评估 21，全部脚本化可重复。
10. **下一步优化？** RAG-lite（正文向量化 + 内存余弦检索，规模论证后不上向量库）、流式 tool_calls 拼装、邮件重置链接（需部署 SMTP）。
