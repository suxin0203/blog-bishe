## 三、各文档分工说明

为了避免重复维护与内容打架，建议后续按下面规则更新：

### `项目说明文档.md`
适合写：
- 项目简介
- 开发目的
- 应用场景
- 系统整体能力
- 项目亮点
- 总体流程概述

不建议写：
- 过细的接口列表
- 太具体的安全实现细节
- 扫码登录专题的大量接口样例

### `功能模块.md`
适合写：
- 模块职责
- 核心能力
- 核心接口
- 角色访问边界

不建议写：
- 大段技术原理解释
- 过多背景介绍
- 与扫码登录专题重复的详细流程

### `系统核心技术.md`
适合写：
- 技术栈
- 分层架构
- 请求处理链路
- JWT / refreshToken
- RBAC 权限控制
- 防重放、安全与上传机制

不建议写：
- 完整模块清单
- 每个功能模块的所有接口
- 与项目说明文档重复的项目背景

### `PC扫码微信小程序登录设计.md`
适合写：
- 扫码登录的业务目标
- 参与角色
- 状态设计
- 数据表设计
- 接口设计
- 联调流程
- 安全控制点

不建议写：
- 整个博客系统的完整介绍
- 所有模块总表
- 与系统核心技术文档重复的通用 JWT 说明

### `开发与进度/开发进度与代办清单.md`
适合写：
- 当前已实现功能
- 当前仍待完善项
- 优先级安排
- 阶段性结论

不建议写：
- 过长的接口说明
- 重复复制功能模块文档内容

## 六、维护建议

后续新增文档时，建议遵循以下规则：

1. 先判断属于“总说明 / 功能模块 / 技术机制 / 专题设计 / 开发进度”哪一类。
2. 一个文档尽量只承担一种核心职责，避免什么都往里塞。
3. 如果某块内容已经有专题文档，其它文档只做摘要和链接跳转。
4. 修改接口或权限规则时，至少同步检查：
   - [`功能模块.md`](功能模块.md)
   - [`系统核心技术.md`](系统核心技术.md)
   - [`开发与进度/开发进度与代办清单.md`](开发与进度/开发进度与代办清单.md)
